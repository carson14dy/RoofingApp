
## Go-live (2026-10-21)
At the owner's decision the hail history is turned on for the public site in this pull request: `main` now builds with `--hail-history` (never `--require-live`, so a failed store download leaves the pages saying the history is unavailable, never an all-clear, and the rest of the site still publishes). The daily job publishes the store as a release asset named after the branch (`hail-store-main.tar.gz` for `main`), one run per branch at a time; each build reads its own branch's asset and falls back to `main`'s when the branch has none; every build waits up to 60 minutes for the same commit's store job before it reads the asset; a store older than three days counts as a failed source. Any store job that finds the earlier shared-name asset `hail-store.tar.gz` removes it (it held the address stage's data). Tests cover each rule, including the wait step's shell under a stub `gh` and the fallback through the build's download. D34 is amended; the About text is unchanged; the MSL clause and MCA 2-6-1017 still gate the address stage (B3). Three review rounds (two lenses each) ran on the change before the push.
